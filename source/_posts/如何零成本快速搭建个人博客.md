下面我将帮助大家通过Hexo和GitHub，零成本快速搭建个人博客~

## 个人博客搭建原理

搭建个人博客，本质就是将你在电脑里写的文章，制作成网页，放在一个持续在线的地方，让别人通过网址访问。
**从文章到网页：**
这里我们不排除有狠人每次写博客都写一个完整的网页上去，但这对于普通人来说还是太困难了。我们更希望我们只写一个md文件，有某些工具帮助我们将md文件渲染成html文件，再进行发布。而在前AI时代，已经有了非常成熟的工具：**Hexo**
Hexo会读取md，把正文转换成html，再将标题、日期、分类等信息填入主题模板，生成完整的文章页面。
Hexo下有许多适配的主题模板：比如Maupassant、NexT、Fluid、Butterfly等等，大家可以在GitHub上面根据喜好挑选。
**服务器由谁提供？**
我们可以在腾讯云内购买服务器和域名，但有人就会问了：主播主播，这种打法太吃经济了，有没有不吃经济的打法？
有的有的，GitHub为我们提供了另一个选择。GitHub Pages能够托管网站生成的静态文件，充当我们博客的服务器；GitHub Actions帮助我们自动化通过Hexo构建网站并发布。
这样，我们就拥有了依托GitHub的个人博客，但域名和访问都要受到限制（需要连接外网才能稳定访问）。

## 开始搭建

1. 检查环境依赖：
```Shell
git --version
node --version
npm --version
```
2. 创建一个Hexo博客：
```Shell
npx hexo-cli init myblog-demo
cd myblog-demo
npm install
```
3. 尝试让博客在本地运行：
```Shell
npx hexo server
```
4. 修改网站名称：
   a. 我们可以在_config.yml修改网站的名称等设置
```yml
title: 我的个人博客
subtitle: 记录学习与生活
description: 这是我的个人博客
author: 你的昵称
language: zh-CN
timezone: Asia/Shanghai
url: https://你的用户名.github.io
root: /
```
5. 写一篇博客：
```Shell
npx hexo new "我的第一篇博客"
```
6. 生成真正可以部署的网站文件：
```Shell
npx hexo generate
```
7. 新建远程仓库并将代码push至远程：
    a. 仓库名为username.github.io
```Shell
git init
git config user.name "你的名字"
git config user.email "你的邮箱"
git add .
git commit -m "初始化 Hexo 博客"
git branch -M main
git remote add origin https://github.com/你的用户名/你的用户名.github.io.git
git push -u origin main
```
8. 启用GitHub Pages
    a. settings->pages->Build and deployment中选择GitHub Actions
9. 添加自动发布配置
    a. 创建.github/workflows/pages.yml文件
```yml
name: Deploy Hexo Blog

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: github-pages
  cancel-in-progress: false

jobs:
  deploy:
    runs-on: ubuntu-latest

    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    steps:
      - name: 下载仓库源码
        uses: actions/checkout@v6

      - name: 安装 Node.js
        uses: actions/setup-node@v7
        with:
          node-version: "22"
          cache: npm

      - name: 安装项目依赖
        run: npm ci

      - name: 配置 GitHub Pages
        uses: actions/configure-pages@v5

      - name: 生成网站
        run: npx hexo generate

      - name: 上传网站文件
        uses: actions/upload-pages-artifact@v4
        with:
          path: public

      - name: 发布网站
        id: deployment
        uses: actions/deploy-pages@v4
```
    ● 这个文件告诉GitHub：每当代码推送至main，就准备一个临时的Linux机器，安装依赖、生成网站，再发布public/中的文件
10. 提交这个自动化工作流文件，等待一段时间，就能在username.github.io中看到自己的博客啦！

## Agent偷懒版

我让codex生成了一个制作博客的提示词，直接将这个提示词喂给Agent让它去做大概率效果也是一样的~

>请帮我创建并发布一个可以正常访问的个人博客，完成实际操作。
>
>我的信息：
>
>- GitHub 用户名：[填写用户名]
>- 博客名称：[填写博客名称]
>- 作者昵称：[填写昵称]
>- 主题：[Maupassant / NexT / Fluid / 由你选择]
>- 内容语言：简体中文
>- 时区：Asia/Shanghai
>- 技术方案：Hexo + GitHub Actions + GitHub Pages
>- 目标网址：https://[GitHub用户名].github.io
>
>请按以下要求自主完成：
>
>1. 先检查当前目录、Git 仓库、已安装工具和 GitHub 登录状态。如果已有博客项目，就基于现有项目完善，并保留已有文章、主题修改和未提交的工作；如果是空>目录，再初始化新项目。
>2. 配置 Hexo、主题和必要依赖，使博客支持手机阅读，并包含首页、文章页、分类、归档和关于页面。默认采用简洁、适合长文章阅读的设计。
>3. 配置网站名称、作者、语言、时区、网址和导航。创建一篇明确标注为示例的欢迎文章，方便我之后替换。
>4. 配置 GitHub Actions：推送到 main 后，自动安装依赖、生成网站并发布到 GitHub Pages。本地和自动构建使用兼容的 Node.js 版本，并提交依赖锁文件。
>5. 我授权你安装本项目需要的依赖、修改项目文件、创建或使用指定的博客仓库、提交并推送本次相关修改，以及启用 GitHub Pages。新建仓库使用公开可见性；已有仓库保持原来的可见性。不要覆盖已有远程内容，不要强制推送，不要上传密码、令牌或私密文章。
>6. 实际运行构建，检查首页、文章链接、分类导航、样式和手机布局。部署后检查工作流状态及线上网站；如有错误，继续排查并修复，直到完成，或遇到确实需要我提供的信息。
>7. 在 README 中写清楚日常操作：如何新建文章、修改分类、添加图片、本地预览，以及提交后如何自动发布。
>
>执行原则：
>
>- 普通配置和实现细节由你选择合理默认值，持续推进。
>- 如果缺少账号登录、必要权限或关键资料，再集中告诉我需要完成什么。
>- 不要索取密码或访问令牌的明文，优先使用已有登录状态或官方授权方式。
>- 如果受环境限制无法部署，先完成可完成的工作，准确说明剩余步骤。
>
>完成后告诉我：
>
>- 博客访问地址和源码仓库地址。
>- 已完成的功能，以及实际检查结果。
>- 我以后写文章时需要做的最少操作。
>- 尚未完成的事项及其具体原因。
